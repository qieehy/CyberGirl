## 改动及原因

第一次对照未能保留末尾 emoji，因此没有提交。这次不通过删掉 emoji、清框换编码或放宽正文核对来取得成功。候选仅改变正文输入：对规范原账号、原生 filehelper 页面和独立窗口中的同一编辑器，用一次 UIA ValuePattern.SetValue 写入完整字符串。保留上游的伪窗口焦点开始/结束、正文核对及 MOVE→DOWN→70ms→UP。

Microsoft 的 [SetValue 文档](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.valuepattern.setvalue) 将它定义为对指定控件写入字符串；本项目在既有前台 PoC 已使用同类接口。它在本机后台是否完整保留中文/emoji、是否不激活微信，仍须这次实测，不能只靠接口声明验收。官方 Qt 5.15.2 [键盘映射参考实现](https://raw.githubusercontent.com/qt/qtbase/v5.15.2/src/plugins/platforms/windows/qwindowskeymapper.cpp) 对独立 WM_CHAR 使用单 QChar 文本事件；这支持避免拆成孤立代理项的设计判断，但不是本机具体丢弃位置的证明。

# 群聊与私聊持续读取

2026-11-20，已实现加入指定会话后的后台持续读取。这里的“加入”是工作台订阅列表中的显式加入，不自动订阅整个通讯录。

## 使用

现有普通微信工作台打开 `/history`，在“持续读取”选择群聊或私聊，填写完整群名／好友昵称或备注，点击加入。首次唯一匹配并成功读取后保存订阅；同名歧义、账号不符或读取失败不会登记成功。页面支持查看、暂停、恢复和移除。

也可使用独立只读服务：

```powershell
.venv/Scripts/python.exe -m wechat_agent.cli history --database <已有账号账本路径> --port 8766
```

使用该服务打印的完整认证链接。需沿用已有微信账号账本和有效窗口元数据，不新建空账本。每个账号仅一个服务拥有订阅读写锁；另一个服务尝试启动相同订阅或加入时返回 `read_manager_in_use`，先关闭原服务再使用。

关闭浏览器不停止服务读取；关闭服务回收任务及原生子进程，保留订阅启用状态。服务重启恢复启用项，暂停项保持暂停。普通工作台的总暂停／断开也停止该服务的订阅读取。移除停止读取但保留离线缓存。

## 实现与边界

- 群与私聊复用原精确联系人解析及原生只读快照工作进程，首次固定规范会话标识的 SHA-256，后续在读取正文前核验。账号、会话类型、规范标识与完整名称都必须匹配，不依赖打开每个聊天窗口。
- 订阅清单和缓存位于现有账号账本旁的 `history/<账号指纹>/` 下。群与私聊缓存分开；原私聊接收游标、发送白名单、模型及发送账本不扩大。
- 每次读取完成后默认等待30秒，同一管理器串行读取；失败指数退避，最长5分钟，记录最近成功时间、错误及下次读取时间。错误时保留旧缓存，不冒充刷新成功。
- 本阶段是最近200条的持续快照更新，不是无损消息归档；高流量或长时间离线可能超出窗口。图片、语音仅显示消息类型，不新增媒体下载或模型外发。
- 微信需运行并满足现有可见窗口、版本、账号合同。短暂错误恢复后自动续读；PID／窗口代际失效仍需先恢复已有账号绑定，不自动绕过身份守卫。托盘支持、自动重新绑定、增量持久归档留待后续。
- 新订阅不装配模型或发送器，不触发自动回复；原指定私聊自动回复保持其独立开关和范围。

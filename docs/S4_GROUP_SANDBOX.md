# S4 合成群被动回复、缓冲与预算

2026-10-27，新增“群沙盒”页面，沿用已有 AI_agent Runtime、SQLite 消息账本与 FakeAdapter。此切片仅支持 `fake` 平台和模拟模型，不使用人格页的真实订阅模型，不连接真实微信群。

## 使用

启动现有 `console` 即可进入“群沙盒”；`--live-model` 仍只控制人格页的单轮真实预演。页面提供固定合成群、成员 A/B，以及普通消息、明确 @、回复最近已确认助手消息三种练习类型。

提交后进入缓冲，处理状态自动更新。普通聊天显示“未触发”；包含有效触发的批次可以产生草稿或保持沉默。只有点击“模拟投递”才调用 FakeAdapter。群动作与主人私聊动作使用独立 API 校验目标作用域，不能混用投递接口。

若选择“回复助手消息”，本群必须已有确认的模拟回执；其他群、其他账号或未确认的回执不能触发引用回复。目标由服务固定，模型没有选择群或账号的能力。

## 策略

| 项目 | 本切片行为 |
| --- | --- |
| 授权 | 固定合成群许可；未知群、未验证来源、自身回声、机器人自身 ID 拒绝 |
| 触发 | 明确 @，或引用本作用域内 CONFIRMED 的助手消息；普通消息本身不调用模型 |
| 缓冲 | 安静 3 秒后出批，持续输入最长 10 秒；最多 20 条，合并输入最多 4000 字符，超限拒绝而非截断 |
| 批次 | 原始消息逐条去重；保留成员 ID、正文和触发标记；最后一条作为批次决策锚点，其他记录标为 MERGED |
| 模型预算 | 每群 30 秒冷却、滚动 10 分钟最多 3 次、上海自然日最多 10 次；开始调用前原子登记，失败或沉默也占用预算 |
| 发送预算 | 与模型预算分开检查，采用相同限额；QUEUED 预留容量，实际提交时间决定发送冷却；UNCONFIRMED 保留占用 |
| 退款边界 | 未提交的失败、取消和过期草稿释放发送预留；模型预算不退款，保守处理取消与未知结果 |
| 上下文 | 只保留本作用域已确认的往返历史；新合法入站推进上下文版本，旧草稿取消、生成中旧结果不能入队 |
| 变更 | 撤销、总暂停、人格更新在推理前及提交前复核；启动初始化不会重新开启已撤销的群许可 |
| 时间 | 缓冲使用单调时钟，持久预算按 UTC 时间戳和 UTC+8 自然日计算；检测到预算记录晚于当前时间时暂停新操作 |
| 恢复 | 重启时 BUFFERED/PROCESSING 取消，不补答；SENDING 沿用 S1 的 UNCONFIRMED 恢复，不自动重发 |

缓冲调度器只管理时间窗口与任务，不增加 Agent 循环。最多同时管理 4 个待出批群、4 个出批任务；实际决策仍受 SocialService 的全局并发界限和 Runtime 串行锁约束。10 秒指缓冲出批时间，模型执行仍可能等待已有任务；TTL 会拒绝过时批次。

当前测试期取原计划中更严格的 **10 次/日**。普通群消息可作为同一批次上下文，但不会触发独立模型观察；本切片没有闲聊语义判定、主动群发或定时追问。

## 存储与兼容

schema 3 → 4 前生成 `.v3-<时间戳>.bak`，新增合成群许可和调用预算表，以及合并输入、引用目标、批次字段。原始 inbox 文本不被合并正文覆盖；提示词指纹按实际合并输入计算。未含引用的旧消息指纹保持原算法，已有私聊去重和真实预演记录继续有效。

群原文与合并输入留在本机消息账本，沿用 10000 条 inbox 总容量。当前页面展示最近 100 条群事件；尚无数据归档/删除或人工未知回执对账界面。

## 关键验证

新增 5 个集成场景：触发/最长窗口/引用/账号隔离；沉默与滚动/跨日预算；未知投递及重启不重放；缓冲上限与撤销/暂停/新上下文阻断；真实 loopback 群接口授权、目标绑定和初始化不恢复撤销。

第一批运行 4 个新增场景及 5 个受影响的既有场景，共 **9 个通过**。补齐 HTTP 路由与启动初始化边界后，仅运行新增的第 5 个群场景，**1 个通过**。合计 10 个关键场景，没有重复全量回归。时间窗口与配额用可控时钟推进，没有等待十分钟或跨天。Ruff 通过。

浏览器实测：成员 A 普通消息 → 缓冲 → IGNORED；成员 B 明确 @ → 缓冲 → QUEUED → 手动 FakeAdapter CONFIRMED。本轮新增 2 条合成群消息、1 次模拟模型调用、1 次模拟提交，0 次真实模型请求、0 次真实消息。S3 真实预演记录仍为 1 条，既有私聊与人格保持不变。

详见 [结构化证据](evidence/s4-result.json)和[群沙盒截图](evidence/s4-group.png)。这些证据不代表真实群消息接收、群账号权限或微信桥可用。

## 下一步

平台无关的主人闭环、人格、真实单轮预演和合成群被动策略已有首个可操作切片。下一步进入微信接入准备：确认本机版本与候选桥兼容性，再设计独立收发 PoC。群真实模型适用范围与真实投递仍需各自证据；主动调度、完整权限管理、保留策略和人工对账尚未完成。

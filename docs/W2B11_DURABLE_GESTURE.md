# W2-B11：持久手势意图、未知结果与现场复查

2026-11-03。阶段 D 已推进到 B11：有界完整手势合同已实现并完成离线验证，真实读取补齐了当前空输入、无遮挡命中和按钮连接事实。**D / V0 仍未通过：没有具备现场资格的替代提交入口，真实发送保持关闭。**

## 已实现

`DirectedClick` 在第一次手势观察之前记录 `CLICK_BEGIN_INTENT`，消耗单次使用权。DOWN/UP 各自先写意图，只有父进程的 SQLite FULL 提交完成并返回确认后才允许子进程继续；取消意图也先尝试记录，记录失败仍对原目标尽力清理。任何部分操作异常都保留 UNKNOWN；取消返回和工作进程退出不被解释为远端撤销。

`SendState` 复用现有 `wechat_send_journal`，没有增加数据库迁移。意图绑定既有 operation/action、规范 filehelper、窗口代际、内容哈希、已消费的 SUBMIT_PERMITTED、固定 W2B 标记及本机 operator 来源。顺序、重复、错误来源/正文、暂停、过期及新消息检查失败均拒绝。清理记录不因暂停或过期而被误当成下一次发送许可。

新的 `gesture_protocol.py` 在既有私有管道上申请持久意图。父进程仍独占主账本，子进程不接收主账本路径。每次提交最多 4 个意图帧，绑定操作/请求序号/意图序号；不接受其他命令阶段的申请。意图申请后必须返回结构化手势结果，不能降级为旧 accepted 布尔值。结果只能是 NOT_STARTED / REQUESTED / UNKNOWN，不会把 REQUESTED 写成投递 CONFIRMED。

结果和取消返回事实追加到 journal；`gesture_summary(operation_id)` 可以在重启后读到最小对账事实。无法找到操作会明确报错，已有提交许可而缺少终态记录时按 UNKNOWN 处理。父进程被中断时仍沿用既有恢复：发件 UNCONFIRMED，通道阻断，旧许可不重放。人工手机确认不自动解除 UI 通道阻断。

发送编排器已经接入父进程记录回调；默认原生后端的提交路径拒绝保持。没有注册真实 DirectedClick 观察器/发射器，也没有允许模型文本或任意目标/坐标的现场入口。普通只读探针现显式采用 `--read-only`，焦点准备仍须显式选择并经过原路径资格检查。

Win32 调用继续限定原窗口和线程、每消息非零时限、BLOCK/ABORTIFHUNG/ERRORONEXIT 组合，不广播、不使用取消超时的标志。按照 [Microsoft SendMessageTimeoutW 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendmessagetimeoutw)，调用返回值与处理结果是不同概念，失败/超时不能自行推导为远端未执行；同一队列还可能忽略超时，因此实际生产适配仍须独立进程/线程边界和 Job 回收。

已有 3 种隐藏自有窗口实验也改为先提交真实 SQLite 意图再发送定向消息，核对成功、DOWN 挂起、UP 挂起；发射器只接受本次自建测试窗口类/PID/代际，拒绝微信或其他窗口。这证明持久调用顺序和超时边界，不作为微信/Qt 路由资格证据。

本轮分组回归累计覆盖 132 个不同用例，全部通过；收尾固定来源/恢复语义检查后，新手势与定向消息两组 **54 passed**，Ruff 通过。C 的接收回归 11 项已包含在受影响回归中，没有重跑真实模型或发消息制造错误。早期两项测试夹具问题（无关闭接口、故障触发器误覆盖 gate 日志）已修正后复验。

## D 的剩余条件

1. **实际入口资格。** B9 对当前进程的窗口过程查询曾被 Windows 以错误 5 拒绝，本轮没有重复被拒绝的查询、提权、注入或把静态注册地址冒充实时入口。当前真实命中和 clicked 连接改善了证据，仍不能证明替代定向消息已经到达正确的 Qt 事件路径。
2. **目标适配。** 在可证实的入口上实现原窗口/线程/控件/正文/几何的每次调用复核，保留 UNKNOWN；当前 B11 IO 仍是注入式离线候选，真实后端继续拒绝。
3. **独立人工通道复核。** 空输入和 pressed=false 已是新的现场事实，原阻断尚未解除。应结合历史人工确认、回收/恢复及新入口资格完成明确复核；不能换账本或新编号直接绕开。
4. **一次新动作验收。** 条件齐备后，在同一受控发送账本中创建一次新的固定标记请求，先固定认证回显基线，程序只提交一次，再查本人全文唯一新回显及手机核对。旧标记/旧 action 不重放；未知结果停止，不重试。

用户界面的 UNKNOWN 表述维持“结果无法确认，已停止，请先核对”。真实主人、群发送及工作台自动回复仍属于后续阶段，本次没有开放。

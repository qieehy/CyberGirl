# W2-B5：定向后端、单次提交与手机人工确认

2026-11-02。**原生定向后端已实现，只有一次尝试取得输入和提交许可；用户已在本对话确认手机文件传输助手看到完整标记，账本登记为 CONFIRMED。自动本地回显和提交后输入状态仍未通过，发送通道保持阻断，W2-B / V0 不标为全部通过。**

后续核查：W2-B6 已验证该自绘按钮的实际可访问动作接口只响应聚焦，不实现 Press；因此本页的“提交”只表示 API 调用，不代表原生发送链路已经验证。手机人工反馈仍按原来源保留，不替代链路验证。原路径已关闭，最新见 [W2-B6](W2B6_POST_SUBMIT_DIAGNOSIS.md)。

## 实现与边界

`native_sender.py` 将 W2-B4 原生会话检查接到每次 UI 动作之前。只有固定进程/窗口、固定二进制、W2-A 账号指纹、本人身份和原生 `filehelper` 同时一致，才接受有界 W2B 固定标记。未向工作台、模型或 HTTP 接口注册真实发送后端。

`wechat_native_worker.py` 运行单次父子协议；其 PowerShell UIA 子进程 `wechat_native_ui.ps1` 只提供限定窗口的观察、一次聚焦、一次 ValuePattern.SetValue 和一次 InvokePattern.Invoke。没有鼠标导航、全局按键、额外回车、清草稿或自动重试，也不调用微信内部方法。

UIA 初次定位改为三个有界结果的类查询：输入框最多 2 个、会话行最多 64 个、按钮最多 32 个；必须得到唯一输入框、唯一选中行和唯一发送按钮，按钮与输入框必须同属 ChatInputView。之后固定这些元素，每次检查 PID、类、可见性、选中状态、祖先归属、RuntimeId 组合哈希、焦点及草稿哈希；规范会话身份仍由原生页面业务键提供。显示标签只作否定筛选。查询阻塞由可终止进程与父进程时限控制。

新增持久 `FOCUS_PERMITTED`，聚焦前也检查策略、暂停、动作有效性和单次顺序。聚焦只使用目标 HWND 的正常前台请求与该输入框的 SetFocus；Windows 拒绝前台请求则停止，不绕过限制。原生账号及目标先验证、空草稿先确认，再请求聚焦；输入及提交仍分别需要持久许可和父子两侧复核。

`KillJob` 现在先终止任务，再查询 Windows Job 的活跃进程数归零，确认 Python 工作进程及 UIA 子进程均退出后才恢复提供方开关。工作进程仍挂起或恢复失败时继续阻断。

首次尝试发现冷启动超过原先总计 7 秒的窗口。已把原生准备单独限为 15 秒，只允许初始化和观察，不授予文本输入许可；完成后开始原有 **7 秒动作窗口**，另留 **2 秒清理**。本机 PoC 显式使用 25 秒外层投递时限；SocialService 默认仍为 10 秒，普通工作台不受影响。准备后、聚焦前和文本动作前继续重查策略。相同已认证 DLL 字节的静态分析只在同一进程内复用，每次仍重算磁盘文件指纹并重新核对句柄/窗口；没有跨进程身份缓存。

## 快照与账本

`wechat_filehelper_source.py` 只打开既定账号的 `message_0.db`、`message_1.db`，逐个取得经页 HMAC 认证的密钥，密钥仅保留内存；完整认证内存快照，发送前只查 `filehelper` 水位。操作后只查同一会话、水位之后的有界新记录。账号变化、文件替换、盐值变化、快照不稳定或分页不完整均拒绝，不扫描其他会话的正文。

该 PoC 用两个固定分片盐值组成账号级代际，外加运行时文件身份检查；这不代表正式轮转、多分片发现或常驻读取器已经实现。

专用账本为 `.state/social/wechat-sender-poc.sqlite3`，与工作台、W2-A 读取 PoC 分开。固定标记为 `W2B-20261102-native-once`；动作来源是本机 operator，没有伪造入站或调用模型。每个请求幂等。替代失败请求必须证明旧动作没有任何输入许可、状态 FAILED、工作进程退出及开关恢复；任何其他动作已取得文本许可后，都禁止再创建这条固定标记的发送尝试。没有把 UNKNOWN 改回可投递状态。

所有获许可的文本操作均属于同一条固定标记，其他联系人、群及收藏的动作均为 0。三个投递请求中，前两个没有获得文本输入许可；只有第三个执行了输入/提交。模型请求及决策为 0。

人工确认只改变 outbox 的对账状态，保留实际 attempt 原来的 UNCONFIRMED，也没有解除 `submission_or_draft_requires_review`。

## 尚未解决的提交后状态

本次限定数据库的首轮读取为 **0 条新记录**，未建立 `local_echo` 证据；不能把手机人工确认冒充数据库回显。

提交后的独立只读观察发现，输入控件 ValuePattern 仍返回完整标记的哈希。尚未区分真实编辑器残留与可访问性值不同步；不能宣称提交后草稿已经清空。没有自动清除该内容，也没有再执行发送。见 [提交后只读观察](evidence/w2b5-post-submit-readonly-2026-11-02.json)。

因此本轮完成的是定向后端、一次提交调用及手机人工确认，尚不满足自动运行所需的提交后检查。通道保持阻断，不启动自动回复或常驻服务。

## 验证与收尾

新增合成场景覆盖原生检查先于动作、旧草稿保护、失焦/换控件/正文变化/禁用按钮、三类单次动作、持久聚焦许可、仅观察不授予输入状态、两个固定分片的新记录及账号/文件变化、独立准备时限、准备后暂停、失败请求替代条件。新增与相关测试最终 **63 passed**，Ruff 通过；PowerShell 语法检查通过。

最终独立检查确认开关原值 0、外层 3 节点，账号仍与 W2-A 相同；见 [恢复复查](evidence/w2b5-final-restored-2026-11-02.json)、[账号复查](evidence/w2b5-account-final-2026-11-02.json)和 [本轮汇总](evidence/w2b5-result-2026-11-02.json)。密钥或明文数据库文件写入为 0，没有安装新依赖、迁移旧用户账本或修改收藏。

下一项 W2-B6 优先做只读诊断：比较当前输入的 ValuePattern/TextPattern 与真实编辑器状态，核对所选分片的写入/回显路径，补齐提交后验证。保留现有草稿与通道阻断；未解决之前不再输入、提交或解除阻断，其他联系人/群发送继续禁止。

接口依据为 Microsoft 官方 [ValuePattern 输入](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/add-content-to-a-text-box-using-ui-automation)、[InvokePattern](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.invokepattern.invoke?view=windowsdesktop-10.0)。本机可用性以上述证据为准，不将 API 调用成功视为送达凭据。

## 1. 用户能得到什么

首轮目标：用户在其他软件工作，微信正常登录、窗口可以被其他窗口遮挡；程序仍能读取指定会话并发送准确文本，不把微信切到前台，不移动真实鼠标，不把输入送到用户当前应用。

分开登记以下能力，不把“后台进程在运行”当作后台操作已实现：

| 等级 | 微信状态 | 验收目标 |
| --- | --- | --- |
| BG1，首轮必需 | 已登录、窗口未最小化，可以被其他窗口遮挡 | 收发均不抢前台、不动真实鼠标 |
| BG2，后续独立验证 | 最小化或收进托盘 | 先查该状态是否可直接操作；若需恢复，仅允许明确支持的不激活显示方式，记录窗口确实被显示过，不能宣称一直隐藏 |
| BG3，首轮不承诺 | 锁屏、桌面会话断开等 | 没有实测证据前显示“当前不可用”，不假定与普通后台窗口等价 |

BG1 通过不自动表示 BG2/BG3 通过。微信程序仍须运行且登录；本计划不实现离线发微信。

## 4. 实施顺序与交付

### B18：独立复现上游完整后台流程

**Review 修订（2026-11-07）：先完成 B18a 离线准入，再进入 B18b 实机。** 固定快照存在两处不能仅靠建议参数消除的差异：

- `bg_sender.send` 即使传 `char_mode="utf16"`，正文不匹配时仍会进入 `for attempt in range(2)`，清框并换编码重写；显式编码不等于关闭试写/重试。必须把内部清框、第二次输入列入效果审查；默认不准入，不能用“只调用一次 send”证明只有一次输入。
- `chat=None` 虽避免 `open_chat`，也会跳过函数内所有 `if chat` 目标检查；传 chat 又会进入按名称匹配/切会话路径。外层开始时核验不能覆盖输入期间切会话的竞争。须证明完整调用期间的稳定目标绑定；若只能靠最小补丁实现，则明确标为“受约束上游对照”，未经修改原版保持未验收。不得为了取得原版成功而放宽目标/草稿约束。

B18a 必须提交配置—效果矩阵（源码位置、默认行为、所选配置、剩余效果、是否补丁），离线覆盖正文不匹配、会话切换、内部清框和异常退出。B18b 仅在这些问题有明确处理且具体动作可审阅时进入。安全范围优先于原版对照的完整性；无可准入原版路线时，可记录原版不适用并评估受约束对照，不把它计作原版成功。


交付一个独立、可回收的原版对照运行器，以及完整导入依赖清单和效果清单。先做静态/离线检查和只读准备，再安排一条明确的新标记实机试验。

1. 通读入口和所有会产生效果的调用，列出初始化、输入、编码探测、清框、切会话、系统读屏、gate 改写、窗口显示和回退行为。明确哪些可通过原生配置关闭，哪些会改变对照条件。
2. 固定原账号与规范 filehelper，预先手动打开空输入；若入口允许，使用“不切会话、不自动显示窗口、显式 UTF-16、不开编码试写、不做前台回退”的参数组合。参数以所选版本真实签名为准，不猜字段名。
3. 原版调用外只做开始前的身份/草稿/进程检查、一次性持久许可、结束后的证据收集和恢复；不在其鼠标手势内插入 UIA 查询或父进程往返。
4. 必须区分“未修改的上游源码＋显式配置”与“为兼容而补丁后的版本”。若必须打补丁才能限制目标或恢复状态，逐项记录，不能再把结果称为未经修改的原版结果。
5. 原版涉及的系统级状态若确有必要改变，先做好保存、恢复和独立回读；实际效果在具体试验方案中明列。无法满足现有操作范围时先停在准备状态，不偷偷删掉相关初始化后仍宣称完整复现。

**通过条件：** 其他应用始终保持前台、鼠标未被程序移动，完整新标记写入正确目标，有唯一新数据库回显及接收端核对，结束后草稿/状态和子进程恢复可核查。原版的 sent / sent_unverified 或空输入返回不单独充当成功证据。

**若失败：** 保留现场，不补发；按初始化、窗口绑定/DPI、输入、点击、结束观察、数据库回显分层定位。一次只改变一个差异。未复现前，不扩大自研窗口过程逆向或继续堆叠点击变体。

### B19：将验证过的后台模块接入现有发送器

交付独立后台后端和显式能力选择。

- 在准入对照成功（明确标注原版或受约束版本）的基础上接入 worker、规范账号/会话绑定、outbox 和持久动作许可，保留相同的初始化、输入和提交行为。逐步接入，每一项接线改变都可与独立对照比较。
- 从后台路径中移除“必须前台、必须真实鼠标命中、必须真实键盘焦点”的错误前提；以经过验证的窗口/控件/原生会话绑定替代。保留已有草稿保护、正文核对、目标限制、幂等及恢复规则，不靠直接删除前台守卫让旧物理路径冒充后台路径。
- 后台模式不得调用 SetForegroundWindow、真实 SetFocus、SendInput、mouse_event、keybd_event 或控件的真实 Click/SendKeys。投递给指定微信窗口的 WM_SETFOCUS 与实际抢系统前台是不同操作，分别审查和记录。
- 默认不允许后台失败后转为前台鼠标/键盘发送；可能已输入或提交时进入 UNKNOWN，停止并请求核对。
- 单独处理提交后 UI 候选名称短暂变化的问题：使用已验证的原生会话/同一编辑器身份和双模式读回区分过渡状态，不以提示名变化直接重发，也不改写历史拒绝记录。

**通过条件：** 接到原账本后的 BG1 新标记独立通过，暂停、草稿、新消息过期、换账号/换会话、断流和崩溃均不能重复发送。前台物理路线只可显式选择，后台模式不能隐式调用它。

### B20：后台接收与持续运行

交付桥接生命周期和后台能力状态，再推进工作台真实接线。

- 分离身份/进程校验与 UI 可见性检查，避免数据库读取因无需使用的前台条件而中止；账号、程序指纹、进程代际和数据作用域校验保持。
- 复用已完成的读取子进程、游标和去重；原生 UI 操作串行化，发送前后核对账号/会话和新消息状态。
- 后台路径准备期间即使失败也不生成第二次发送；重启恢复从已提交游标继续，不重放已提交或不确定的 outbox。
- 先用固定文本/模拟模型完成后台接线，后续再接已有实际 Runtime。工作台明确区分“后台可用”“需显示窗口”“等待登录”“需人工核对”，不把前台试验成功显示为后台可用。

**通过条件：** 在其他应用保持前台时持续读取并完成一次明确授权的后台发送；读取器/服务重启后无重复落账或重复发送。负向测试尽量使用离线故障注入，实机发送条数保持有界。

### B21：最小化与托盘状态

BG1 稳定后，再分别验证最小化和托盘隐藏。若上游要求恢复可见，则先验证不激活显示是否可用及是否改变前台，能力名称如实标为“恢复可见后后台操作”。不得把先激活、再还原焦点称为全程不抢前台。

锁屏及远程会话断开不纳入本轮完成条件；需要时单独立项验证。

## 5. 验收与证据

| 场景 | 必须观察到的结果 |
| --- | --- |
| 微信被其他窗口遮挡 | 原应用保留前台，程序不移动鼠标，唯一新标记送达 |
| 输入框已有草稿 | 不覆盖、不清理、不发送 |
| 账号/会话变化 | 停止，不能按显示名称误发 |
| 用户正在其他应用工作 | 微信不激活，程序文本不进入当前应用；不收集该应用正文 |
| 非 ASCII 文本 | 阶段允许后用中文及 emoji 验证完整正文，不能只用 ASCII 证明 UTF-16 路径可用 |
| 发送后查询失败/无唯一回显 | UNKNOWN，保留已发生事实，不自动重试 |
| 进程退出/服务重启 | 原动作不重放，游标不回退，状态恢复可核查 |
| 最小化/托盘 | 单独记录直接可用、需不激活显示或不支持，不借用 BG1 结果 |

前台/鼠标证据使用开始前、运行期间及结束后的观察，并结合调用记录和静态检查；只比较起止点不足以证明中间没抢前台。采样不能证明任意短暂变化绝不存在，记录采样间隔和可观测范围。证据不保存其他窗口标题、用户输入、聊天正文或密钥。

每个动作记录输入/提交是否可能发生、上游返回、唯一回显、人工确认、退出/恢复结果。工具中的成功返回、消息入队和鼠标位置不变都不能代替送达证据。程序可确认与需人工确认的边界分别显示。

### 超时、互斥与恢复

现有 `sender.py` 的动作超时上限为 7 秒、准备上限为 15 秒；上游存在互斥等待、树初始化和每 UTF-16 码元默认 0.04 秒的输入等待。不能直接套用旧超时，也不能无界延长。B18a 按锁等待、初始化、正文码元数、提交、观察及清理分别给出预算，设置正文长度上限和总期限；通过测试后才决定 B19 的配置/代码变更。

后台与前台后端共用同一账号/微信进程代际的跨进程写互斥；上游锁与项目锁固定获取顺序，验证两个 worker/两个服务实例不能同时操作。取消或超时不等于撤销已排队的窗口消息：阻止新动作，回收子进程，独立核查状态；未回收或恢复失败继续阻断。系统读屏/gate 等共享状态只能恢复本动作拥有的变更，检测外部变更时记录冲突并停止，不盲目覆盖。

区分“尚无输入效果且有证据”“输入可能发生”“提交可能发生”和“唯一送达确认”；后两者无法核实时沿用 UNKNOWN/阻断语义。崩溃注入至少覆盖许可持久化前后、输入后、提交前后、回显前后、确认落账前后。动作 ID 和许可消费必须跨重启保留；恢复只做核对，不重新调用 send。

### 可复核验收包

每条标记保存：测试编号、源码/依赖摘要及补丁、微信构建与进程代际、目标绑定、输入/提交次数、各阶段耗时、前台事件/鼠标观察覆盖、数据库基线与唯一新记录标识、人工核对和恢复结果。唯一回显须同时匹配原账号、规范目标、发出方向、完整预期正文及基线后新记录，不能仅凭时间或相同文本判定。

普通诊断日志只存正文摘要和长度；预期固定测试标记保存在受限试验清单，读取正文仅用于内存比对，不保存其他聊天或前台应用内容。前台监测记录句柄/进程标识和单调时钟，结合事件观察、采样及调用审查；用户正常切换其他应用可以发生，微信被激活或程序向其他应用注入即失败。真实鼠标移动须区分用户输入与程序调用，无法区分时不作肯定结论。

B20 首轮观察窗口定为 30 分钟，期间包含一次读取器重启和一次服务重启；第二条已确认动作在重启后不得重放，第三条使用新的动作及许可。负向崩溃矩阵优先离线完成，实机不额外制造 UNKNOWN。此窗口只证明限定持续运行，不代表全天稳定或无人值守已开放。

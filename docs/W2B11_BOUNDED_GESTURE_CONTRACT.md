# W2-B11：有界完整手势离线合同

2026-11-03，离线合同已实现并通过关键验证，见 [W2-B11 实施及现场复查](W2B11_DURABLE_GESTURE.md)。**一次完整、定向、有时限的操作将不能确认的结果持久记为 UNKNOWN 并停止。不是原子操作保证，不要求将取消调用误认作撤销证明；本文不放行真实发送。**

## 入口和目标

复用 `directed_click.py` 的单次状态机，保留 filehelper 固定标记、原生账号/页面核验、初始空输入快照和完整正文哈希约束。没有模型发起、任意文本/坐标参数、联系人/群发送或全局键盘/鼠标回退。

按下前仍须复核原 PID/HWND/进程创建时间、接收线程、同一输入页/控件、按钮、DPI、物理客户区坐标、真实命中、前台、焦点、捕获和硬件干扰。B8 未通过的实时命中/焦点和 B9 未建立的实际窗口入口不能由静态报告自称通过。

当前已有草稿须保留。实施阶段只做离线验证；现场前必须重新检查实际草稿、历史人工确认和通道阻断，形成独立的复核步骤。不能自动清草稿、重放旧标记，或通过新账本/新操作编号绕过现有阻断。

## 持久许可与意图

父进程的既有单次提交许可仍是必要条件。CLICK_DOWN_INTENT、CLICK_UP_INTENT 不能仅写入测试列表或普通缓冲日志，必须在相应调用前持久化。CLICK_CANCEL_INTENT 也应先尝试持久记录；该清理记录失败不得阻止针对原窗口的尽力清理，但结果必须保持 UNKNOWN，不能恢复发送资格。实现需明确记录归属、与 operation_id 的绑定、写入失败处理及崩溃后读取方法，再连接候选回调。

记录只含操作标识、固定阶段、时序和必要状态，不含正文、原生对象地址、RuntimeId、密钥或凭据。单次使用权在第一次观察前消耗；同一对象、动作或意图不得重放。

## 操作与超时

只对原绑定窗口、代际和线程执行定向消息。保留有界消息时限和 Job 回收，采用已有约束的 SendMessageTimeout 调用参数。发送器须在每个调用前独立核对目标，不接受外部传入任意 HWND。

DOWN 未开始时可以返回 NOT_STARTED。DOWN 可能已经进入目标后，超时、异常、目标/控件/几何变化、日志失败或 UP 无法确认均为 UNKNOWN；不重新定位、不向新目标释放、不重试。

DOWN 处理返回后，只有原身份、正文、控件和几何复核仍通过，才记录并请求一次 UP。必要的取消只针对仍能验证的原窗口，属于尽力清理。无论取消是否返回，都不能证明 Qt 状态或待处理事件已经清空，也不能将 UNKNOWN 改为“未执行”。工作进程退出同样不能撤销目标应用已接受的事件。

## 返回、对账和界面

完整调用返回最多是 REQUESTED。后续双模式空输入、严格关联的本地回显和人工接收证据分别记录，不以调用返回或本地回显直接确认投递。UNKNOWN 阻断后续发送，只允许只读对账和明确的人工复核；人工确认收到了消息，也不自动证明编辑器/手势状态已复位或解除通道阻断。

用户界面只需清楚显示“结果无法确认，已停止，请先核对”，不把内部消息名或指针检查放进操作流程。

## 离线验收范围

先使用合成观察、临时日志/账本和自建隐藏接收窗口，验证持久记录先于效应、所有失败出口、窗口代际变化、部分操作超时、日志失败、重复调用与子进程回收。自有窗口接收器必须继续拒绝微信 HWND，不能把这个实验当作 Qt/微信兼容性证据。

该切片结束交付实现、离线证据、风险边界及具体现场步骤，真实提交仍默认关闭。只有目标适配和现有草稿/通道复核条件满足，才另行开展既定 filehelper 单条新动作验收；不以本合同替代这些条件。

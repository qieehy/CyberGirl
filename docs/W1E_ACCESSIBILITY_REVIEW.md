日期：2026-10-29。**源码审查与本机 DLL 离线匹配完成；发现一个优先候选，尚未验证运行时启用。** W1 聊天控件和 W2 收发出口仍未通过。

## 已确认的初始化机制

候选为 [fanyuantaier/wechatauto-replica](https://github.com/fanyuantaier/wechatauto-replica/tree/6e603974bbac3bda93d88bbd6995510ae2547f5c)，固定提交 `6e603974bbac3bda93d88bbd6995510ae2547f5c`，提交时间 2026-10-25。保存了 README、LICENSE、accessibility.py、uia_driver.py、两个初始化模块及 tools/wake_uia.py，共 7 个文件；许可证文本为 Apache-2.0。仅静态阅读，没有安装、import 或执行上游代码。

`accessibility.py` 的常规路径会枚举微信模块，在 Weixin.dll 中搜索 Qt 无障碍相关字符串、引用指令及字节比较模式，然后请求目标进程的 VM_READ/VM_WRITE/VM_OPERATION 权限，将候选位置写为 1。之后检查根节点或第一层子节点是否出现 `mmui::` 类名；成功就保留修改并写入用户目录缓存。

因此它不是单纯的 UIA 查询初始化，也不等同于正常公开配置开关。该路径未看到远程线程或 DLL 注入，但确实修改运行中微信的内存。`uia_driver._wake_accessibility()` 在激活失败后还会设置系统读屏标志；公共 `wake(..., set_flag=True)` 也有这条默认回退。不能直接将整套初始化挂到本项目启动流程。

上游版本兜底表仅包含 4.1.11.22、4.1.13.65、4.1.15.13、4.1.15.53，没有 4.2.0.9。它允许对未知版本扫描，并不意味着这些版本已实测兼容。

## 下一切片的具体范围

建议 W1-F 先实现独立受控验证器，默认仅做预检，实验写入须作为明确操作。它应锁定当前 DLL SHA-256 与唯一候选，核验目标进程/模块/内存页和 0/1 预期值，禁止任意 RVA、候选逐个试写和系统读屏回退。第一阶段只读结果可在继续分析授权内执行；实际改变微信进程之前需明确说明并取得该操作的授权，普通“研究初始化方式”不当作写进程内存授权。

临时启用的可审阅实验应只有一次：记录原值 → 写入单个已锁定候选 → 只读统计控件类与模式 → 无论成功失败都恢复原值并回读确认。不发消息、不调用模型、不采集 Name/Value/正文。恢复失败必须单独报告，不能继续尝试其他候选。进程崩溃/断电/强制终止时无法承诺 finally 一定执行；实现与说明不能宣称绝对可回滚。

应先用合成进程访问接口完成一个覆盖写后异常与恢复失败的关键验收，再考虑实际实验。获得 `mmui` 树只是 W1 的阶段证据，群身份、去重、引用关联和真实回执继续由 W2/W3 分别验收。

本轮完成 W1-E，无需再运行相同状态下的 W1-D 原始树检查。未建立自动回复或真实发送入口。

## 启动与使用

在 `D:\qieehy\WeChatAgent` 的 PowerShell 中运行：

```powershell
& '.\.venv\Scripts\wechat-agent.exe' console
```

打开终端打印的完整地址（包含 `#auth=…`）。默认端口 8765，可用 `--port 8766` 改端口；这是本项目页面，与 Hiddify 的 12334 代理端口不同。启动时生成的本地访问凭证进入该标签页的 sessionStorage，地址栏随即移除片段；刷新页面仍可使用，服务重启后须使用新的完整链接。退出终端会停止服务。

默认账本为 `.state/social/sandbox.sqlite3`，可通过 `--database` 指定另一份沙盒账本。一个账本只允许一个进程持有；工作台运行期间不要同时对同一账本执行 `social-demo`。工作台不读取 OAuth 凭据，不依赖代理，不消耗订阅额度。

1. **人格设定**：编辑名字、表达方式和背景偏好，保存产生新版本。载入旧版本后保存也会产生新版本，历史版本不可覆盖。
2. **工作台**：输入合成消息，生成草稿；点击“模拟投递”才产生 FakeAdapter 回执。固定模拟回复可验证版本接线，不能用于判断真实模型的人格质量。“测试沉默”快捷项不产生待发草稿。
3. **消息回放**：查看最近 100 条消息的原文、回复、人格版本、状态、回执和提示词指纹；“验证去重”只验证原事件的幂等处理，不重新生成或发送。版本列表显示最近 30 个版本。

“暂停沙盒”取消待发草稿；恢复不会补发。人格更新也取消旧草稿，已在生成中的旧版本结果不能落入待发队列。草稿有效期沿用 S1 的 120 秒，提交前再次核验。

## 实现边界

- SQLite schema 1 → 2 自动迁移：迁移既有账本前产生 `.v1-<时间戳>.bak`，保留消息/回执。旧记录显示“旧版记录”，不会伪造未保存的人格版本或提示词指纹。
- 不可变人格快照与固定系统约束分开装配。人格不能配置目标联系人、账号、权限或工具。推理前保存版本、实际输入上下文快照和装配指纹；只有已确认投递的往返进入历史。
- 人格保存要求 `expected_version`，冲突返回 409，界面保留输入；暂停操作也核对策略版本。
- HTTP 服务仅监听 `127.0.0.1`；严格 Host、写请求 Origin、随机 Bearer 凭证校验，无开放 CORS。静态页面不包含凭证或账本数据；API 才提供受保护数据。设置 CSP、no-store、禁止框架嵌入和无 Referer。
- 请求大小、连接任务数量和处理时长有界。前端用 `textContent` 显示用户内容，无动态 HTML 注入；无需外部 CDN 或新增依赖。
- 同一进程复用已锁定的框架依赖；没有安装 Hermes 或改动相邻 AI_agent。

## 关键验证

新增 3 个关键场景：旧数据库迁移与备份；人格冲突、旧草稿取消及生成中版本栅栏；真实 loopback HTTP 的认证/Origin/Host、编辑、草稿、确认、去重完整流程。另运行受影响的 5 个 S1 核心场景，覆盖原子性、会话隔离及真实子进程崩溃恢复。

首次共 8 个场景中 7 个通过，1 个因测试使用错误的 `httpx.Headers.update` 参数形式失败。修正测试构造后仅重跑该 HTTP 场景，通过；未重复全量测试。Ruff 通过。

浏览器实测完成保存 v2、生成、模拟投递、回放依据和去重。发现投递后练习区提示仍停留在“等待确认”，已改为按当前账本同步；仅复验这条受影响的浏览器流程，确认显示“已确认投递”。截图见 [工作台](evidence/s2-console.png)，结构化记录见 [S2 证据](evidence/s2-result.json)。浏览器练习共新增 2 条合成消息、2 次固定模型调用和 2 次 FakeAdapter 提交，真实模型与真实消息均为 0。

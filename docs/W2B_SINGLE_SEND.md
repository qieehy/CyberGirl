# W2-B1：单次发送控制层

2026-11-02。**发送控制层已实现并离线验证；真实 UI 后端和单次微信发送尚未验收，W2-B / V0 尚未通过。** 范围仍限规范 username 为 `filehelper` 的私聊。

## 实现

- `send_state.py` 在原 Ledger 内保存动作、窗口代际、内容哈希、读取基线、启用原值及阶段记录。输入/提交许可先持久提交，随后才调用子进程，每个动作各限一次。每次许可复核暂停、草稿过期、新消息和绑定；同一账本只允许一个活动 UI 操作。
- `sender.py` 的 `WeChatSendAdapter` 接入现有 SocialService，必须显式注入读取器、租约及工作进程，没有默认真实后端。内部时限最多 7 秒，子进程回收最多 2 秒，与现有 10 秒外层时限协调。取消后等待清理结束，再交还控制。
- `AccessibilityLease` 固定同一进程句柄和窗口指纹，记录后临时启用，结束后恢复并回读。原来已启用则保留。日志失败不能阻止实际恢复；工作进程未确认退出则不恢复其提供方租约，记录未恢复状态并阻断后续发送。不启用系统读屏。
- `send_process.py` 使用最大 16 KiB JSON 行管道，绑定 operation_id 与严格递增序号，拒绝超大响应、重复 JSON 键及错误操作。初始化前加入 Windows kill-on-close Job，父进程退出时回收本次工作进程树；微信进程不加入 Job。
- `send_worker.py` 是工作进程侧的单次协议。父进程观察后，原生输入和提交之前再次检查目标、焦点、控件和草稿；发生异常即终止，不重复执行。它没有自带微信 UI 后端。
- 输入观察要求规范原生 username、账号/窗口依据、空输入框及正确焦点；输入后要求同一控件、完整正文哈希和焦点一致。显示名称不被接受。合同只校验一致性，不能代替真实身份依据；底层仍须定向操作并使用一种经过验证的发送方式。
- `SendState.queue_marker()` 允许受信本机操作者创建有界 W2B 固定标记，不调用模型。记录为 `operator` 来源，不冒充平台入站、不制造读取游标或模型决策，也不进入模型聊天历史。同一 request_id 幂等，内容变化报冲突。没有暴露给模型、HTTP 工作台或普通聊天消息。
- 回显要求操作前持久基线、规范会话、本人发送者、全文一致且唯一，拒绝来源冲突和没有基线的分片。`local_echo` 后仍为 UNCONFIRMED。已许可输入的操作要求检查原生状态后才能恢复后续发送；人工对账不自动解除此限制，也不重发。

## 迁移与验收

schema 5 → 6 增加发送操作、阶段记录、通道状态和 inbox.origin。打开旧库前备份，迁移在事务内；旧消息默认 origin=source。操作中断后重开保持投递不确定并阻断 UI 通道，不重放旧动作。本轮只打开测试临时账本，未迁移用户工作台及 W2-A PoC 账本。

新增 8 个综合场景覆盖：输入前拒绝；输入后目标/正文/暂停/过期/超时；单次提交与错误/冲突回显；取消、日志失败和恢复失败；许可事务、重启和迁移回滚；真实合成子进程的协议/超时/迟到动作/父进程退出；工作进程再次核验；固定标记来源及幂等。最终新增和受影响场景合计 **37 passed**，Ruff 通过。期间修正合成子进程的测试模块导入路径后，单独复验进程场景通过，再完成最终 37 项验证。见 [离线证据](evidence/w2b1-offline-2026-11-02.json)。

API 依据：[Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)、[Python 3.12 asyncio subprocess](https://docs.python.org/3.12/library/asyncio-subprocess.html)。异常回收由本机合成子进程验收；这些子进程没有微信 UI 能力。

## 现场观察及下一切片 W2-B2

computer-use 只读快照显示当前 HWND 68894 停留在文件传输助手，但可访问性只暴露外层 3 节点，尚未取得规范会话 username、可验证输入控件及发送方式。显示标题不能作为发送许可。本次未临时启用微信可访问性、未输入、未发送、未调用真实模型。

下一项为有界只读身份/输入能力取证，明确规范 username 与当前可编辑会话的证据链，再实现定向 UI 后端；不自动搜索导航、不覆盖草稿。随后接上 W2-A 的限定内存快照提供器，取得操作前基线和新回显；保持密钥不落盘、不扫其他账号或全部历史。通过离线验证后，仅对已核实的文件传输助手执行一次唯一固定标记，记录本地回显和接收端核对。未确认则结束，不重试。

正式多分片代际、常驻读取器、真实工作台与主人/群闭环继续按后续计划推进。见 [操作范围](WECHAT_OPERATION_SCOPE.md)。

后续进展：W2-B2 已完成真实输入能力取证，定位输入框与发送按钮，但已查字段未建立规范会话身份。真实发送继续关闭；详见 [W2-B2 取证与路线](W2B2_INPUT_CAPABILITIES.md)。

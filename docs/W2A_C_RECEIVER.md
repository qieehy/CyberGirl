# 阶段 C：限定账号真实接收

2026-11-03，**阶段 C 已完成**。用户明确确认范围为《微信接入实施计划》第 6 节“限定账号真实接收”，并已从手机发送唯一标记。原账号和内置 `filehelper` 的文本观察、同批幂等重放、全新读取子进程恢复均通过。真实接收器没有模型请求或程序发送。旧发送账本及其阻断状态保持；接收账本不会提供任何发送许可。

## 实现

- `receive_state.py` 在主账本 schema 7 保存账号级随机代际，绑定已认证账号、目录路径及文件身份。代际不会随普通进程重启或新增分库改变。分库独立绑定文件身份和认证页头 salt 指纹，消息 ID 包含分库代际。分库消失、替换或账号目录替换时停止，不能自动换代后重扫。
- 每次连接先核对固定 EXE/DLL、PID/创建时间/HWND，再读取当前账号；必须匹配显式账号指纹，才进入该账号目录。仅枚举该目录下最多 256 个名称、最多 16 个 `message_N.db`，不回退到其他账号。密钥和认证内存快照只在独立读取子进程中存在。
- 首次必须显式 `--baseline-now`。当时的各分库尾部及本地编号水位随目录登记保存；即使登记后、游标创建前中断，也恢复原基线。普通重启恢复原游标；后续新增分库从零分页，以免跳过轮转时已写入的首批消息。只查询 filehelper 与所需 Name2Id 映射，不拉取其他会话历史。
- 按 `(sort_seq, local_id)` 严格排序，每页最多 32 条。正式读取要求 `local_id INTEGER PRIMARY KEY AUTOINCREMENT`；非法位置、编号截断或新增高编号落到旧排序游标之前时停止。每次快照认证及来源变化检查沿用 W2-A，不依赖修改时间判断“没有更新”。
- 主进程独占 Ledger，消息处置、复合游标与本地编号水位在同一事务提交后才能 ACK。子进程只允许一份未确认批次，没有主账本路径。IPC 有运行随机代际、单调请求编号、重复键检查及 1 MiB 帧上限；单次请求最多 60 秒，每轮最多 100 页，未读完的下一轮从已提交游标继续。
- Windows 子进程在取得任何密钥前加入 kill-on-close Job，限制整个 Job 内存为 1 GiB。退出、取消、异常或超时均终止并检查子进程及后代；没有独立驻留后台服务。一个分库快照连接关闭后才处理下一分库。
- 普通文本严格 UTF-8，最多 4,000 字符/16,000 字节。按 `WCDB_CT_message_content` 的明确标记支持普通 Zstandard，不凭解码失败猜压缩。解码前限制帧内容大小、字典 ID 和 1 MiB 窗口，限制输出并拒绝截断/尾随数据/多帧。字典压缩及未知类型停止且不推进游标，不返回占位文字。非文本只登记类型处置，不把正文带入父进程。

压缩元数据规则依据腾讯 [CompressionConst.hpp（固定提交）](https://github.com/Tencent/wcdb/blob/47f2d7e944ff72b16558210310a9f74b475ee5c0/src/common/core/compression/CompressionConst.hpp)，源码 SHA-256 为 `e2b85436bfce6e8f44c766fa05cef83055100d4214c008436ca9abec113f4b16`。解码 API 参照 [python-zstandard 官方文档](https://python-zstandard.readthedocs.io/en/0.25.0/decompressor.html)。新增可选依赖 `zstandard==0.25.0`，Windows CPython 3.12 wheel SHA-256 为 `ffef5a74088f1e09947aecf91011136665152e0b4b359c42be3373897fb39b01`，已用 `--require-hashes --only-binary=:all:` 安装。BSD-3-Clause 许可随包保存到 `assets/licenses/zstandard-0.25.0-LICENSE.txt`。

## 入口与边界

显式运行 `scripts/run_wechat_receiver.py`，提供当前进程绑定与已核实账号指纹。默认账本为 `.state/social/wechat-receiver.sqlite3`，默认只运行一轮；首次加 `--baseline-now`，后续不加也可恢复。工作台默认仍为原模拟模式，不会隐式开启真实接收。

验收参数支持指定 W2A 唯一标记、提交后同批重放，以及自动更换读取子进程核对恢复。输出和 evidence 仅含计数、布尔值与指纹，不含密钥、账户原文、源路径或聊天正文。内存快照仍物理包含该分库其他会话页面；SQL 查询范围受到限制，不声称所有 Python/SQLite/操作系统内存副本经过安全擦除。

filehelper 手机同步消息的发送者是当前账号，正确处置是 `self_echo`，不会伪造为主人来信。其他发送者的 inbox/观察路径由合成场景验证，真实主人和真实群仍属于后续范围。分库轮转在离线场景验证，不人为修改微信数据库制造轮转。

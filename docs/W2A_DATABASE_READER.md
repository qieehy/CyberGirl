# W2-A：限定文件传输助手的新文本读取 PoC

2026-11-02。本机 Weixin 4.2.0.9 的数据库读取可行性已得到实证：当前账号、两个选定消息分片的页认证和内存快照通过；用户从手机发送的一条文件传输助手标记被准确读取。**这不是常驻监听器、主人私聊或完整群接入验收。**

## 本次结果

1. 固定当前 PID 34044、HWND 68894、创建 FILETIME 134380654003431728 及已有 EXE/DLL 指纹。只申请查询/读内存权限，未修改进程标志或微信内容。
2. cfg 账号字段匹配唯一账号目录。参考上游的 cfg 主密钥派生未通过选定数据库页认证，保留 [失败记录](evidence/w2a-header-probe-2026-11-02.json)，未改用其他账号或密钥缓存。
3. 显式改走同进程 WCDB 配置对象路线，匹配选定数据库页的 HMAC；不安装上游自动化包。页密钥仅在短时探针进程内存中存在，不输出/保存。来源与修改说明见 [引用说明](WECHAT_DB_SOURCE_NOTICE.md)。
4. 两个消息分片约 70.9 MB / 67.9 MB，分别认证 17,319 / 16,587 页，内存 SQLite 均能读取文件传输助手的复合游标。第二分片基线还包含 6 个有效且已提交的 WAL 帧。见 [分片 0](evidence/w2a-filehelper-baseline-v2-2026-11-02.json)、[分片 1](evidence/w2a-filehelper-shard1-baseline-2026-11-02.json)。
5. 发现实际 WAL 按 4 MiB 预分配，末尾不是完整帧边界。原严格长度检查拒绝该文件；按 SQLite 格式，只在先遇到完整帧的旧 salt 后忽略旧尾部，仍拒绝当前代际的截断帧与坏校验。修正及对应关键验证后，快照通过。首次失败证据保留于 [快照记录](evidence/w2a-filehelper-baseline-2026-11-02.json)。
6. 用户从手机发送一次唯一标记后，仅查询基线之后的文件传输助手消息，读到 1 条；正文精确匹配，发送者通过该分片 Name2Id 映射为当前账号本人。因此来源账本记录 `self_echo`，不进入业务 inbox、不决策、不发送。重复回放新增 0 条；账本重新打开保留游标，探针退出后由另一进程只读核对也仍为 1 条来源记录。见 [新增标记结果](evidence/w2a-filehelper-new-marker-2026-11-02.json)、[持久化复查](evidence/w2a-persistence-check-2026-11-02.json)。

结果是正确过滤自身回声，不是“未收到消息”。当前原生 PoC 没有验证其他发送者进入 inbox 的路径；该路径已有离线合同测试。

## 实现与数据边界

- 新增最小 `keyprobe.py`、`wcdb_probe.py`、`snapshot.py`、`reader.py`，以及显式运行的 `scripts/probe_wechat_database.py`。默认启动工作台不会导入或启动真实读取。
- `cryptography==50.0.2` 作为可选读取依赖；Windows x64 / Python 3.12 的三个实际 wheel 版本和哈希固定于 `requirements/wechat-read-win-py312.lock`，安装时验证哈希。见 [依赖记录](evidence/w2a-reader-dependencies-2026-11-02.json)。没有安装 OCR、上游 UI 自动化或完整 whale_gril。
- 只读取得加密 DB/WAL 后检查身份、大小、时间及第二次内容哈希，来源变化则停止。每页 HMAC 校验、WAL 代际及连续校验和、提交边界均验证；忽略未提交事务。128 MiB DB / 32 MiB WAL 上限，不悄悄截断。
- 解密在内存完成，SQLite 使用内存连接、只读查询模式及内存临时存储。没有密钥文件、明文 DB 缓存或聊天正文诊断日志。分片物理包含多个会话，因此快照内存可能包含其他会话的数据；SQL 只查询文件传输助手和必要的发送者映射，不做历史导出。Python/SQLite/操作系统可能保留临时内存副本，不能声称所有副本都经过安全擦除。
- 消息查询按 `(sort_seq, local_id)` 分页，最多 100 条，发送者从同分片 Name2Id 查找。未知发送者或正文无法严格 UTF-8 解码时停止，不返回占位文字并推进游标。目前不支持压缩文本或结构化群 @/引用。
- 本次真实来源处置仅存于 `.state/social/wechat-reader-poc.sqlite3`，没有迁移或改动用户工作台账本。该 PoC 的数据库代际取**选定分片**页头 salt 指纹，只适用于本次固定单分片验证；正式多分片接收须改用稳定账号级数据库代际及分片清单，不能在切换分片时重置账号代际、制造重复事件。

真实探针本轮没有发送消息（唯一标记由用户发送），模型请求 0，微信进程写入 0，收藏等内容修改 0。没有常驻后台监听进程。

# W2-B4：当前输入页的原生规范会话身份

2026-11-02。**当前输入页已通过原生业务会话键核验，确认为 `filehelper`，并与 W2-A 已认证数据库的账号一致。身份取证出口通过；真实发送后端及 W2-B / V0 仍待完成。**

## 原生证据链

延续 W2-B3 的瞬时 UIA RuntimeId → Qt accessible cache → QObject 映射，仅沿选中行和输入框的 QObject 父链读取，没有枚举对象的子树或任意堆对象。父链上限 24；实际选中行 18 层、输入框 19 层，都终止于同一个真实 `mmui::MainWindow`。输入框拥有唯一 `mmui::ChatMessagePage` 祖先。

固定 DLL 的 Qt 元数据声明 `ChatMessagePage::OnNewSessionDataLoaded(std::string)`。静态检查可从该方法的第 8 项分派追踪到 RVA `0x1C68940`：代码比较页面 `+0x1D0` 的 std::string 与传入会话键的长度、正文，并将一致的键用于会话类型判别。此前追踪的判别代码包含公众号 `gh_`、应用 `@app` 及内置会话 `newsapp` 分支，因此该字段属于业务会话键，不采用会话行的显示名载荷。

新增 `scripts/inspect_wechat_session_key.py` 复现元数据类型、分派目标、字段访问及相等比较的字节检查，先验证整个 DLL 指纹。它只读取磁盘文件，不加载 DLL、不调用目标函数。见 [静态复现结果](evidence/w2b4-static-session-key-2026-11-02.json)。

运行时同时核对固定页面类、metaobject、vtable 和字段访问代码，按有界 MSVC std::string 布局读取字段，只接受规范 ASCII 标识符；证据仅保存是否精确等于 `filehelper`，不输出其他会话的 ID。实机读到精确的 `filehelper`，首次对象读取合计 **7,411 字节**，全部观测字段在结束时再次回读一致。见 [最终原生身份结果](evidence/w2b4-native-identity-final-2026-11-02.json)。

## 可复用检查与结果语义

`qt_memory.verify_current_filehelper()` 负责原生目标核验：

- 从受信、无密钥的账号读取器取得当前账号，先与 W2-A 页认证证据中的指纹比较。
- 验证输入框、选中行及共享主窗口的原生归属，读取当前输入页的业务键；不是 `filehelper` 则拒绝。
- 复核所读字段稳定性，并再次核对账号未变化。返回结果不包含原始账号名、RuntimeId 或指针。

`probe_wechat_input.py --native-current-session` 要求原生父链模式和既有认证账号证据；账号证据还必须包含成功的页 HMAC 验证。身份未通过时返回 `not_verified` 和失败退出码。汇总中的 `canonical_identity_verified` 只有在原生键、稳定性及账号共同通过时才为真；`native_send_enabled` 仍为假。这是可供后端调用的检查，尚未接入真实发送事务，不宣称已经消除并发界面变化或完成发送前后的全部控制。

探针在进入更深层原生读取前，仍使用当前选中行和输入框的内置显示标签作否定筛选：不是候选页面就停止。显示标签不会授予任何发送许可。本轮一次现场检查发现窗口已切到其他会话，按该规则停止并恢复；用户手动切回文件传输助手后才继续取证。见 [拒绝记录](evidence/w2b4-business-key-2026-11-02.json)和 [首次完整身份成功](evidence/w2b4-business-key-ready-2026-11-02.json)。

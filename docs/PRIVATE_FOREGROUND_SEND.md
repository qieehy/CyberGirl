# 指定私聊前台与后台发送

2026-11-18。用户要求微信切到前台不影响自动回复，明确扩大之前仅后台遮挡的运行范围。

## 问题与实现

此前拒绝发生在输入前：一次微信切到前台，一次输入框实际含四个空白字符。模型生成已成功，不能把这些失败描述为模型不可用。四个空白已按精确输入框身份和双重文本读取清除；清除动作引起微信获得前台焦点，未发送微信消息，随后已确认输入框双重读取长度均为0、准备与清理通过。

1. 仅指定私聊发送器显式向子进程传递 `--allow-foreground`。前后台使用同一绑定窗口消息链路，不调用全局键鼠，不激活其他会话。
2. 保留原生账号／联系人／进程／窗口／编辑器验证、空草稿和完整正文校验、逐次输入与提交日志、唯一回显关联。最小化和托盘仍拒绝。
3. 观察器继续记录前台切换；私聊模式不把该事件当作失败。原filehelper及实验默认仍保持后台限制。真实焦点处在当前聊天窗口时允许保留；后台仍验证伪焦点释放。
4. 单来源单动作规则及失败不自动重试保持不变。页面显示前台/后台能力，也会明确展示最近一次发送失败原因，避免仅看到“自动回复已开启”而误以为上次已经发送。

## 关键检查

26项模拟测试通过：前台切换策略、前台真实焦点允许与后台伪焦点释放、旧后台默认拒绝、单次提交与去重、回显关联、自动回复停止／恢复、采样失败仍拒绝等；JS和Python语法检查通过。真实准备检查确认当前选定会话双重空输入与原生身份，进程清理及gate恢复通过；准备期间窗口未位于前台，不据此宣称已完成真实前台消息提交。

已重载并启用：reading=true、auto_reply.enabled=true、capabilities.foreground=true、background=true，当前模型为用户通过页面选择并保存的gpt-5.6-luna，媒体模式保持开启。

不重发此前三个失败动作。真实前台/后台提交以启用后的自然入站消息与唯一回显为准，不额外发送测试码或假造入站。

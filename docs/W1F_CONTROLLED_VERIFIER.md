## 行为

- 锁定 Weixin.exe、4.2.0.9 Weixin.dll 的 SHA-256、映像大小及唯一候选；没有任意地址参数，也没有多候选试写。
- 指定 PID 后核对进程路径、实际加载模块、唯一可见窗口、内存映像页和 18 字节指令与磁盘的一致性；候选当前值只接受 0/1。
- 默认进程权限为 `0x410`（查询及读取），没有 VM_WRITE/VM_OPERATION；只读模式读取固定指令与一个标志字节，不读取聊天、凭据或其他业务数据。
- 显式实验模式才申请写权限。先持久记录原值；写入调用前就标记“可能已修改”，覆盖“写入发生后 API 才报错”的情况。校验异常、超时及可捕获中断进入恢复路径，恢复后必须回读确认。
- 恢复遇到非预期并发值不覆盖；恢复失败单独报告，不能因后续日志失败掩盖。不替换进程句柄、不对新 PID 补发操作、不更改系统读屏设置。
- 原值已为 1 时，实验模式也不再写入。`--observe-only` 则在只读预检后调用已有原始 UIA 元数据采集器；它不读取 Name、Value、标题或消息文本。

恢复确认只指候选字节，不承诺撤销 Qt 在观察期间创建的对象或缓存。进程被强制终止、目标退出、断电、页面变化等情况下无法保证恢复；这些限制不能由 finally 消除。

## 只读结构观察结果

执行时重新核对正常桌面用户可见窗口所属 PID，仍为 44256；以只读权限完成预检并采集 Raw/Control 两个视图。两个视图均获得 29 个节点，根节点 ClassName=mmui::LoginWindow、FrameworkId=Qt，达到深度 8 的采集上限，无读取异常。没有读取任何 Name/Value/窗口标题，也未调用 ValuePattern 获取值；记录中的 Pattern 字符串仅表示支持该接口。

该结果解释了为何候选值为 1、同时不能确认聊天能力：它来自新进程的登录窗口。之前已登录进程 30376 的三节点观察仍是独立证据，不能将两个进程的结果拼成“启用成功”。本轮没有改变候选标志，也没有证据证明登录窗口的原值由本项目造成。

新增窗口类型分类：仅根类为 mmui::MainWindow 且具有 Edit/List、采集无异常且未截断时才标记聊天控件候选；LoginWindow 和搜索窗口即便有编辑/列表也不能通过。一个针对登录/搜索窗口误判的关键场景通过，只运行此新增场景及 Ruff，未重复既有 3 个事务测试或重新采集真实 UI。
